# 多实例与端口共存（实测）

> 验证日期：2026-09-29
> 环境：`dsh` 0.2.0-rc.2 · Windows · Node v24.13.0
>
> **结论：可以同时运行多个 DSH 实例，各占一个端口，互不干扰。**

---

## 1. 为什么验证这个

两个原因：

1. **安全地做实验**：改配置 / 装插件可能搞坏环境。若能开一个"一次性实例"验证，
   就不必拿正在用的会话冒险。
2. **启动器需要它**：启动器要拉起 `dsh web`，必须确认不会把用户已经开着的实例搞崩。

---

## 2. 实测过程

### 2.1 隔离手段

关键是用**独立的 `DSH_HOME`**，避免两个实例争抢同一个 profile 目录（`patchReload: live` 下会互相触发重载）：

```powershell
$testHome = "$env:TEMP\dsh-port-test-home"     # 独立 home
$env:DSH_HOME = $testHome                       # 只影响这个子进程
node <dsh>/lib/bin.js web --port 3099 --no-open
```

> ⚠️ `--no-open` 必不可少，否则会弹出浏览器窗口抢焦点。

### 2.2 结果

| 检查项 | 结果 |
|---|---|
| 新实例监听 | ✅ `127.0.0.1:3099`（PID 98184） |
| 原实例监听 | ✅ `127.0.0.1:3080`（PID 127888）**同时存在** |
| 启动输出 | ✅ `dsh web: http://127.0.0.1:3099/?token=FsD3hTsS…`（43 字符） |
| 新实例根路径 | ✅ HTTP **401**（认证正常） |
| **token 兑换** | ✅ HTTP **303** + 下发 **1 个 cookie**（端到端可用） |
| 原会话根路径 | ✅ HTTP **401**（未受影响） |
| **原会话 PID** | ✅ 仍为 **127888**（**全程未重启，会话没断**） |
| 清理后 | ✅ 3099 已释放；原会话 3080 仍在 |

### 2.3 清理

```powershell
Stop-Process -Id <测试实例 PID>
```

实测**优雅关闭即生效**（无需 `-Force`），端口随之释放，临时 `DSH_HOME` 可整个删除。

---

## 3. 结论与用法

### 3.1 可以做的事

| 场景 | 做法 |
|---|---|
| 安全试插件 / 试配置 | 用独立 `DSH_HOME` + 独立端口开一个临时实例，玩坏就删 |
| 同时开多个工作区 | 各实例独立端口即可（但注意 §4 的注意事项） |
| 启动器拉起 DSH | ✅ 可行；但必须处理"端口已被占用"的情况 |

### 3.2 ⚠️ 注意事项

1. **端口必须各自不同**。`--port 0` 可让 OS 分配空闲端口，
   但 ⚠️ **cookie 绑定 `host:port`** → 端口变了 cookie 就失效，用户需重新用 token 兑换。
2. **`DSH_HOME` 必须隔离**（若只想一次性实验）。
   共用同一个 home 时，两个实例会同时读写 `cordis.patch.yml` 等文件，
   在 `patchReload: live` 下可能互相触发重载。
3. **共享同一个 `DSH_HOME` 的实例会共享会话与凭据** —— 这不是 bug，是想清楚要什么就行：
   - 想复用登录态/会话 → 共用 home
   - 想做无副作用实验 → 隔离 home
4. **不要用 `--host 0.0.0.0`**（CLI 硬拒绝，见 [plan.md](../plan.md) §5）。

---

## 4. 对启动器的启示

1. **启动器不需要"独占"DSH** —— 用户可能已经开着一个，启动器应能检测端口占用并给出选择
   （换端口 / 复用已开实例 / 关闭旧实例）。
2. ⚠️ **换端口会让 cookie 失效** → 若换了端口，必须**重新走 token 兑换**（启动器在做这件事，所以无感）。
3. **可提供"安全模式"**：用临时 `DSH_HOME` 启动，用于排障或试用插件，不影响用户主环境。
   这是本次实测最直接的副产品。
