## 2. 执行原则

1. **一次只改一件事**，改完立刻验证并 `commit`（见 [AGENTS.md](../AGENTS.md) §1）
2. **先验证再实现**：任何"这条链路能不能通"的疑问，先用最小代价测掉，不要写完几百行才发现方向错
3. **不动当前会话**：需要实验就开临时实例（独立 `DSH_HOME` + 独立端口）
4. **每个阶段有明确门禁**，不通过不进入下一阶段
5. **随时可停**：S4 之后的核心价值已经成立，后面都是增强

### S1 — 🔴 决定性验证：`timed` 模式（20 分钟，只读，零风险）

**做什么**

确认 `ask_user_question` 是否处于 **`timed` 模式**。

```powershell
dsh --profile web --dump-config | Select-String -Context 0,8 'tool-ask-user'
```

或直接验证行为（更可靠）：
用 `ask_user_question` 问一个**带很短 timeout** 的问题，观察超时后是否返回 `pending` 而不是失败。

**为什么这是第一步**
官方 `dsh-tool-ask-user` 的默认值是：

```js
mode: z.union(["legacy","timed"]).default("legacy")
```

- `legacy`（**默认**）= 阻塞式 `ask()`。**你不在场，agent 就干等，问题也不进可回答投影** → **核心功能直接不成立**
- `timed` = `askTimed()`。超时返回 `pending`，**agent 继续干活，问题仍可回答** → 正是我们要的

**三种可能的结果与对策**

| 结果 | 含义 | 对策 |
|---|---|---|
| 已是 `timed` | 🎉 最好的情况 | 直接进 S2 |
| 是 `legacy` | 核心价值受阻 | 评估改 profile patch 为 `timed` 的影响（会改变现有工作流），**并告知你后再改** |
| 工具压根没启用 | 需要先启用 | 一并处理 |

**完成判据**：明确知道是哪种，并记录到 [todo.md](../todo.md) 的 A1。
**这是唯一一个"不成立就要改方向"的验证点。**

### S3 — 装承载层：`dsh-pet`（50 分钟，**已知有版本闸门风险**）

**已知事实**：`dsh-pet@0.2.12` 声明了 11 个 `@deepseek-ai/dsh-*` peer，范围**全是 `^0.1.1-rc.2`**，
而运行时是 `0.2.0-rc.2` → semver **判定不兼容**（`^0.1.x` 上界 `<0.2.0`）。

**做法（按成功率排序）**
```powershell
# ① 先试 npm（最省事）
# 素材随本包分发，无需另装 dsh-pet

# ② 被拒则授予精确版本豁免
dsh plugin --profile web version-exemptions        # 先看运行时版本
dsh plugin --profile web allow-version dsh-pet@0.2.12 --dsh-version 0.2.0-rc.2 --accept-risk

# ③ 仍不行则从源码构建（lib/ 不入库，必须 prepare）
git clone https://github.com/PC2005-cloud/dsh-pet.git
cd dsh-pet\dsh-pet; npm install; npm run prepare
dsh plugin --profile web add file:<绝对路径>
```

**完成判据**：宠物出现在界面上（网页浮层或桌面小窗）。
**失败也不要紧**：架构上 L1 不依赖 L2 —— **核心功能必须能在没有它的情况下工作**。这条会在 S4 被强制检验。

### S4 — ★ 核心实现：R0 提问触达（**本项目存在的理由**）

**做什么**（Host 侧 + 承载侧）
1. 订阅 `user-questions/request` 与 `approval/request`（25 条转发事件白名单里**仅有**的两条 waterfall，且**重连会重放**）
2. 读 `userQuestions` 投影拿待答清单
3. 提交回答 `ctx.userQuestions.answer(agent, callId, answer)`
4. 推送到承载层显示（**角标 + 题干 + 选项**），点选即答

**必须先确认的实现细节（A3）**
`user-questions/request` 在**客户端插件**里的具体挂钩点（槽位/服务名）—— 这是唯一还没落实的技术细节。

**完成判据（三条缺一不可）**
- [ ] agent 提问后，**不切到浏览器**就能看到问题
- [ ] **点一下选项**就能回答，agent 收到后继续
- [ ] **超时后离开一会儿再回来，问题仍在，仍能补答** ← 核心场景

**降级检验（强制）**：临时卸掉 `dsh-pet`，确认提醒仍能通过系统通知/网页浮层到达。
**不通过则说明分层被破坏，必须修架构。**
