# 学校 Outlook：没有 API 时怎么接

> 背景（维护者 2026-11-03）：学校 Outlook **只有网页版**，不给第三方接入、没有 token；
> 网页版经常要重新 2FA；而 **Outlook 手机版的登录不容易过期**。

## 结论先说

**推荐「转发到可访问邮箱 + IMAP」**，而不是去自动化学校网页。
理由：学校 OAuth/Graph 走不通，网页自动化会和 2FA 打持久战，而转发规则**只需设置一次**、
之后完全稳定 —— 且转发到的 Gmail 正好复用我们已经规划好的双向能力。

---

## 四条路的对比

| 方案 | 原理 | 稳定性 | 一次性工作量 | 风险/限制 |
|---|---|---|---|---|
| **A. 转发到 Gmail + IMAP** ⭐ | 在 Outlook Web 建一条「转发规则」到你的 Gmail，然后读 Gmail | **高**（不依赖学校会话） | 5 分钟（一条规则 + 一个应用专用密码） | 学校可能禁用自动转发；只覆盖**设置之后**的新邮件；回复走 Gmail 身份 |
| B. 持久化浏览器会话 | Playwright 用固定 profile 登录一次，复用 cookie 抓收件箱 | 中（会话会过期） | 1–2 小时（含 noVNC 远程登录） | 每次过期都要人工重新 2FA；页面改版即失效；可能违反学校使用条款 |
| C. 手机 App + Android 自动化 | 用 Mika 在手机上操作 Outlook App（登录不易过期） | 中 | 半天（要有可常开的安卓机） | 依赖设备常在线；App 自动化脆弱 |
| D. Graph API / IMAP 直连 | 官方接口 | — | — | **你的租户不给**，走不通 |

> B/C 的本质都是"模拟人操作"，而 2FA 的存在就是为了阻止这件事。
> 只有 A 是**让邮件主动来到我们能稳定访问的地方** —— 这才是工程上更省心的解。

---

## 方案 A 的落地步骤

### 1) 在 Outlook Web 建转发规则（一次性）

1. 打开 Outlook 网页版 → **设置（齿轮）→ 邮件 → 转发**
2. 勾选「启用转发」，填入你的 Gmail 地址
3. **建议勾选「保留转发邮件的副本」**（否则学校邮箱里看不到，不利于对照）
4. 保存

如果「转发」被管理员禁用，试试替代路径：
- **规则（Rules）** → 新建规则 → 条件「发件人/主题/收件人」→ 动作「重定向到」或「转发到」
- 仍不行 → 只能退回方案 B

### 2) Gmail 侧开启 IMAP + 应用专用密码

1. Google 账号 → 安全性 → 开启两步验证
2. 生成 **应用专用密码**（16 位），给 `dsh-assistant` 用
3. 确认 Gmail 设置里 **IMAP 已启用**

### 3) 交给助理

凭据放 `~/dsh-assistant/data/gmail.json`（仓库外）：

```json
{
  "user": "you@gmail.com",
  "appPassword": "xxxx xxxx xxxx xxxx",
  "imapHost": "imap.gmail.com",
  "smtpHost": "smtp.gmail.com",
  "readOnly": true
}
```

然后我们按 [ASSISTANT.md §13](ASSISTANT.md) 的约定实现：
- **读**：IMAP `UIDVALIDITY + UID` 增量、`Message-ID` 去重、只存结论不存正文
- **写**：默认关；要回复时先起草、**经你确认**才发（邮件不可撤回）

> 注意：转发来的邮件里，`From` 仍是原始发件人（学校系统），
> 所以「谁发的」不会丢；但**回复会以 Gmail 身份发出**。要保留学校身份就只能走方案 B。

---

## 方案 B 的落地要点（如果 A 被管理员禁掉）

1. 在 ubuntu 上跑一个**带 GUI 的浏览器**（Xvfb + noVNC），用固定 profile：
   ```
   chromium --user-data-dir=/home/taco/.outlook-profile
   ```
2. 你通过 noVNC 手动登录一次（含 2FA），cookie 落在 profile 里
3. 助理用 Playwright 连这个 profile 抓收件箱列表（只读，不点任何链接）
4. **会话过期时**：抓取发现被重定向到登录页 → 直接给你发 Telegram「Outlook 会话过期，需要重新登录」
   （而不是静默失败）

**必须接受的代价**：平均每隔几天到几周要你手动登录一次；页面改版要跟着改选择器。

---

## 建议的推进顺序

1. **先确认学校是否允许自动转发**（这是唯一的分岔点，2 分钟就能试出来）
2. 允许 → 走 A，我把 Gmail 读写做出来（等你给应用专用密码）
3. 不允许 → 再上 B，我先把「持久化浏览器 + 过期检测 + 通知你重新登录」做出来

**在你确认之前我不写邮件相关代码** —— 两条路的实现差别很大，先避免白做。
